[기준 그림체]
지브리 애니메이션처럼 따뜻한 손그림 수채 풍: 부드러운 윤곽선, 따뜻한 햇빛과 그림자, 수채 번짐, 세밀한 풀·나뭇잎·빛, 맑고 포근한 색.
3D 모델은 쓰지 않고, 2D 손그림과 부품 애니메이션으로 생동감을 낸다.
- 실제 지브리 작품의 캐릭터·장면을 따라 그리지 않는다. 그림 안에 글자·숫자·로고를 넣지 않는다.
- 0단계에서 '스타일 기준표' 1장(색 팔레트, 선, 빛, 질감 예시)을 만든다. 이후 모든 이미지 생성 때 기준표를 참고 이미지로 함께 쓰고, 같은 '그림체 공통 문장'을 프롬프트 앞에 붙인다.

[캐릭터 기준 생김새: 사진 대신 이 설명을 쓴다]
사용자의 기준 사진 10장은 컴퓨터에 있어서 쓸 수 없다. 아래 설명을 쓰고, 코드를 zip이나 GitHub 연결로 구했다면 source/src/art/petphotos.ts에 들어 있는 머리 그림(배경을 지운 WebP, data URI)을 꺼내 얼굴·털색 참고 이미지로 쓴다. 사용자가 사진을 첨부하면 그 사진을 우선한다. 품종 이름과 생김새가 달라도 설명을 따른다.
- 뭉치(maltese): 작고 복슬복슬한 크림빛 흰 강아지. 동그란 머리, 까만 동그란 눈, 작은 까만 코, 노란 목걸이에 금색 방울 이름표.
- 초코(poodle): 붉은 갈색(살구빛) 곱슬털 토이 푸들. 털이 동그랗게 부푼 머리, 까만 눈과 코, 꼬리를 세움.
- 식빵(corgi): 주황빛 황금색 털에 크림색 주둥이·가슴. 아주 크고 뾰족하게 선 귀(안쪽은 밝은 털), 동그란 짙은 갈색 눈, 까만 코, 순한 얼굴.
- 보리(shiba): 살구빛 크림색의 복슬복슬한 강아지. 길게 늘어진 귀, 크고 촉촉한 짙은 눈, 갈색 코. 턱을 앞발에 괴고 엎드린 모습이 잘 어울림.
- 콩이(schnauzer): 검정과 황갈색·크림 무늬의 허스키 닮은 강아지. 또렷한 파란 눈, 눈썹 무늬, 뾰족한 귀.
- 냥이(koshort): 주황 치즈와 흰색 고양이. 연두빛 노란 눈, 분홍 코.
- 구름(russian): 검정·흰색 턱시도 고양이. 초록 눈, 흰 가슴과 주둥이.
- 라떼(siamese): 갈색 줄무늬에 흰 털이 섞인 날씬한 고양이. 노란 눈, 줄무늬가 있는 긴 꼬리.
- 모찌(fold): 통통한 갈색 줄무늬 고양이. 흰 가슴·주둥이, 동그란 연두빛 노란 눈(놀란 표정), 분홍 발바닥.
- 솜사탕(persian): 복슬복슬한 연한 크림색 아기 고양이. 큰 청록색 눈, 분홍 코와 귀 안쪽.

[그림 파일 구조: 0단계에서 새로 만든다]
1. 이미지는 저장소 맨 위 art/ 폴더에 WebP로 둔다: art/<묶음>/<id>.<내용해시 8자리>.webp
   내용이 바뀌면 이름이 바뀌어 태블릿이 새 그림을 받는다.
2. art/art-manifest.json: {"files":[{"u":"art/...webp","b":바이트}, ...]}
3. source/src/art/artmap.ts: 그림 id → 경로 표. 컴포넌트는 이 표로 그림을 찾는다. 그림이 없거나 불러오기에 실패하면 기존 SVG 그림을 그린다. 일부만 적용돼도 앱이 깨지지 않게 하기 위해서다.
4. source/scripts/art_check.mts를 새로 만들고 package.json "check" 스크립트 맨 끝에 추가한다. artmap.ts의 모든 경로가 ../art/에 실제로 있는지, art-manifest.json에 있는지, 크기 상한을 넘지 않는지 검사한다. 그림이 하나도 없으면 통과한다. 그림보다 코드가 먼저 올라가면 검사가 실패해서 사이트가 바뀌지 않게 하는 안전장치다.
5. source/scripts/sw.template.js에 precacheVoices와 같은 방식으로 art-manifest.json의 그림을 설치 때 미리 저장하는 코드를 넣고, 이미 받은 파일은 다시 받지 않게 한다. source/scripts/build_pwa.py의 서비스워커 버전 해시에 art/art-manifest.json 내용도 넣는다.
6. 그림을 HTML 안에 넣지 않는다(data URI 금지). 첫 화면에 필요한 그림만 먼저 불러오고 나머지는 필요할 때 불러온다.

[작업 범위와 규격]
A. 캐릭터 (가장 중요): source/src/art/Pet.tsx
 - 10마리 전부 전신을 새로 그린다. 얼굴·털색·무늬는 위 설명과 같게 하고, 귀·턱·몸은 잘린 데 없이 완성한다. 새 그림이 있으면 지금 쓰는 사진 머리(petphotos.ts)는 쓰지 않는다.
 - 움직이도록 부품으로 나눈다: 머리, 몸통, 꼬리, 앞다리 2, 뒷다리 2(가능하면 귀 2), 감은 눈 덮개, 벌린 입. 각 부품은 투명 배경이다. 목·어깨·꼬리 뿌리 같은 이음부는 움직여도 틈이 안 보이게 겹치도록 넉넉하게 그린다.
   방법 ① 같은 캐릭터의 부품 시트를 생성하거나, 방법 ② 전신 1장을 그린 뒤 Python으로 부품을 오리고 가려진 부분은 이미지 편집으로 이어 그린다. 둘 중 검사를 통과하는 쪽을 쓴다.
 - source/src/art/petrig.ts에 마리별 리그 정보를 둔다: 부품 위치, 회전 기준점(목, 꼬리 뿌리, 귀 뿌리, 어깨·엉덩이), 눈 위치, 꾸미기 기준점(머리 위, 두 눈, 목, 가슴, 등, 앞발 2).
 - 자연스러운 움직임: CSS transform 애니메이션, ease-in-out, 부위마다 조금씩 늦게 따라오는 겹침 동작.
   숨쉬기(몸통 3.5초 주기로 1~2% 늘었다 줄었다, 머리는 0.1초 늦게 따라감) / 눈 깜빡임(2.5~6초마다 무작위, 0.12초) / 귀 쫑긋(5~10초마다 무작위) / 꼬리(강아지는 빠르게 좌우, 고양이는 느린 S자) / 고개 갸웃(말을 들을 때) / 말할 때 입 열고 닫기(onSpeaking 신호에 맞춤) / 점프(웅크림 → 도약 → 착지 때 살짝 찌그러짐 → 복귀) / 걷기(통통 튀며 다리 교차) / 기쁨(제자리 깡충, 꼬리 빠르게) / 잠(느린 숨, 눈 감음, z) / 사랑(하트)
   기존 Motion(bob, jump, cheer, wiggle, none, fly, hop)·Mood(happy, wow, think, sleep, love) 이름과 Pet 컴포넌트 props는 그대로 두고 동작만 새로 만든다. 기기 설정이 '움직임 줄이기'면 움직임을 줄인다.
 - 성장(아기·어린이·어른)은 기존 growthOf()를 그대로 써서 아기일수록 머리가 크고 몸이 작게 보이게 한다.
 - 검사: 그림이 가장자리에 닿지 않을 것(사방 4% 이상 여백), 귀·꼬리를 포함해 잘린 곳이 없을 것, 설명과 털색이 맞을 것. 마리마다 동작 미리보기 GIF(숨쉬기·깜빡임·꼬리·점프)를 Python으로 만들어 확인한다.

B. 꾸미기 아이템: data/pets.ts ITEM_LIST, Pet.tsx의 Hat·Glasses·Neck·Clothes·Shoes·Toy·ItemIcon
 - 지금 48개 → 약 100개 (모자 20, 옷 18, 안경 12, 목걸이 16, 신발 12, 장난감 22 정도).
 - 기존 id는 절대 지우거나 바꾸지 않고 뒤에 추가만 한다. 같은 slot과 for(dog/cat/both) 조합은 20개를 넘기지 않는다. DROP_ORDER가 20개까지만 돌기 때문에, 넘으면 앱이 켜지지 않는다.
 - 아이템은 리그의 꾸미기 기준점에 붙어 해당 부품과 함께 움직인다(모자·안경 = 머리, 목걸이·옷 = 몸통, 신발 = 발). 옷은 몸통 그림 모양대로 잘라 몸에 맞게 보이게 한다. 10마리 모두에 맞도록 마리별 보정값을 둔다.
 - 미리보기: 마리마다 슬롯별 아이템을 하나씩 입힌 모습을 한 장으로 만들어 위치를 확인한다.

C. 간식: data/pets.ts SNACKS, Pet.tsx SnackIcon, engine/gifts.ts SNACK_WEIGHT
 - 6개 → 약 20개 (강아지용·고양이용·같이 먹는 것 골고루). 새 간식은 SNACK_WEIGHT에도 추가해야 실제로 선물로 나온다. points는 1~3.

D. 집 안 꾸미기: data/home.ts ROOM_SLOTS·FURN, art/Home.tsx FurnArt, screens/Home.tsx
 - 자리 10개 → 16개 정도 (바닥재, 선반, 시계, 천장 모빌, 쿠션, 벽 장식 등 추가). 자리마다 고를 것 6~8개.
 - 기존 자리 id·위치와 가구 id는 그대로 두고 추가만 한다. 벽지·바닥은 이어 붙여도 티가 안 나는 무늬로.

E. 집 밖(마당) 꾸미기: 새 기능
 - 강아지 집·고양이 집 밖을 꾸미는 화면을 만든다. 배경은 '강아지 마을', '고양이 마을' 느낌으로. 저장 장소 이름은 'doghouse-out', 'cathouse-out'.
 - 저장은 기존 deco·bought(setDeco, buyFurn)를 그대로 쓴다. 저장 구조와 두 기기 합치기 규칙을 바꾸지 않기 위해서다.
 - 자리 12개 정도: 울타리, 우체통, 화단, 정원 길, 등불, 나무, 깃발 줄, 벤치, 그네, 연못, 문 장식(화환), 창가 화분. 자리마다 5~6개.
 - 집 건물 그림은 1장으로 하고, 집 색깔은 같은 그림에 색조 필터(hue-rotate 등)를 씌워 4~6가지로 고르게 한다.
 - 기존 집(House) 화면에서 "마당 꾸미기"로 들어가고, 꾸민 마당은 집 화면에도 보이게 한다. 값은 집 안 가구처럼 재료 1개.

F. 놀이터: data/home.ts PARK_SLOTS·FURN(park), screens/Home.tsx ParkScreen
 - 자리 10개 → 14개 정도, 자리마다 5개. 기존 id·위치는 그대로.

G. 배경: 첫 화면, art/Scene.tsx Backdrop(meadow, river, sky, night, castle, cave, beach), art/Library.tsx(library), 집 안·마당·놀이터 배경, 그리고 0단계 목록에서 찾은 다른 배경 전부
 - 크기 2560x1600. 놀이터처럼 가로 2560 좌표인 곳은 3840x1200. 극장판 애니메이션 풍경처럼 세밀하게: 먼 산, 하늘, 구름, 빛줄기, 풀잎, 꽃, 물결.
 - 겹 그림: 하늘(뒤) + 풍경(중간) + 앞쪽 풀·꽃(투명)으로 나눠 깊이감을 준다. 구름 흐르기, 풀 흔들림, 꽃잎·나뭇잎·반딧불(밤) 같은 은은한 움직임을 CSS로 넣는다(움직이는 것은 동시에 25개 이하).
 - 아래쪽 22%는 캐릭터가 서는 땅·바닥으로 단순하게. 말풍선·버튼이 놓이는 곳은 너무 복잡하지 않게.

H. 집 짓기: data/pets.ts BUILDS, art/Build.tsx BuildArt·MatIcon
 - 강아지 집·고양이 집·놀이터 완성 그림을 각 1장 그린다. 부품을 n개 지은 단계는 완성 그림을 부품 순서대로(또는 아래에서 위로) n/전체만큼 보이게 한다. 부품 이름·음성·순서는 그대로.

I. (이미지 한도가 남을 때만, 맨 마지막) 낱말 그림 카드
 - 지금 이모지로 보이는 낱말 그림(data/curriculum.ts WORDS, data/jamo.ts ex)을 같은 그림체 이미지로 바꾼다. 그림이 없으면 이모지를 그대로 쓴다.
